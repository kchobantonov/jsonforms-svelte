# Read-only and hidden action audit

This records the owned mutation boundaries reviewed for spec §15.8 and TODO P1.13. It covers the three native families and their extended packages. Renderer-owned actions must recheck current enabled, read-only and visibility state at dispatch; `restrict` continues to govern the supported size and bound constraints.

| Mutation path                                                             | Final guard and focused evidence                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Text, mask, numeric, Boolean, finite-choice, slider and temporal controls | Each native family's `util/composition.svelte.ts` rechecks enabled, read-only, visibility, path, schema and data at commit. `PendingControlPermissions` passes 16/16 per family, including live hide after queued password/enum edits; `NativeReadonly` and `ConfigReadonly` cover inspection and precedence.                                                                                  |
| Array, expandable-array and list/detail Add, Remove and Move              | `useCollectionAction` checks visibility, permissions, owner schema/path, data, config and UI options before and after pending-edit flush. `useDeletionConfirmation` checks the same ownership before opening and accepting Delete. Shared `pendingAction.svelte.spec.ts` passes 18/18; the fresh family/locale/host production gate passed 108/108 before the later visibility changes.        |
| ArrayChoices, ChoiceCards, enum arrays and tuple tails                    | Shared `arrayChoices.svelte.ts`, `choiceCards.svelte.ts` and `additionalItems.svelte.ts` check visibility, enabled/read-only state and applicable `restrict` limits. Native `EnumArrayRenderer` checks the same state at its direct checkbox handler. ArrayChoices plus ChoiceCards pass 35/39/35 across Flowbite/Shadcn/Skeleton; tuple pagination passes 6/6 and enum arrays 7/7 per family. |
| Dynamic properties and mixed-tree commands                                | Dynamic Add/Rename and mixed-tree Rename route through the shared collection coordinator; Delete routes through confirmation. Name, target and permission checks run at commit. Mixed node writes also recheck visibility and nested read-only paths. Dynamic-property suites pass 25/25 per family; mixed-tree commands pass 25/24/24.                                                        |
| Recursive Object/AllOf Create and formatted-number cell input/Clear       | Direct `handleChange` callbacks recheck visible, enabled and read-only state. Object suites pass 18/18, AllOf suites 8/8 and formatted-number cell suites 8/8 in each family.                                                                                                                                                                                                                  |
| Composite-cell Empty/Remove and isolated dialog Apply                     | Shared `useCompositeActions` includes visibility in its live Empty predicate; Remove uses deletion confirmation. The dialog receives that enabled predicate and rechecks the original target before Apply. CompositeSummary passes 28/30/28 across families.                                                                                                                                   |
| File, color, duration, null, Monaco and Cron controls                     | Extended adapters use the native guarded `binding.onChange` boundary. File Add/Remove/Clear also check visibility before starting I/O and cancel a pending read on hide (new mounted case per family). Cron's direct write and open-picker predicate checks visibility; Cron suites pass 23/23, 23/23 and 20/20.                                                                               |
| AG Grid cell edits and collection actions                                 | `onCellEditRequest` checks visible, enabled/read-only, source index and row key before direct dispatch. Add/Remove/Move use the collection and deletion coordinators. Native-edit suites pass 5/5 per extended family.                                                                                                                                                                         |
