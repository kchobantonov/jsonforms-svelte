Source review at the revisions in the [upgrade plan](spec-upgrade-plan.md). The [source inventory](renderer-source-inventory.md) lists concrete files and current tests. This audit distinguishes existing code from verified contract support. Later browser acceptance is recorded in the affected rows and [verification baseline](verification-baseline.md).

Current progress is summarized in the [TODO checkpoint](TODO.md#progress-checkpoint--2026-11-02). This audit mixes original source findings with later bounded acceptance updates. Consult the linked verification evidence before reopening work.

The R01–R65 row review is complete at the 2026-11-02 checkpoint: 52 gap columns were reconciled against accepted workstreams or an explicit not-verified boundary, and thirteen already expressed the current evidence or a declared boundary. R33's focused family files now cover detail focus, label/registry selection and pagination boundaries; R15's browser-owned native datalist popup remains a documented platform verification exception after P8.2 acceptance. The [spec-section evidence crosswalk](spec-section-evidence.md) completes the P8.1 spec and ledger reconciliation.

## Status and common acceptance

- **Partial:** implementation exists, with known missing behavior.
- **Not verified:** implementation exists, but the complete current contract has not been executed.
- **Unsupported:** no implementation/consumer for the role was found in the inspected Svelte registries and source searches.
- **Accepted functional profile:** the declared renderer behavior has executed native and production acceptance; cross-cutting accessibility, visual, performance and release gates remain in their own TODO items.

The entries below focus on Shadcn source. All three Svelte base sets currently have the same 50 `.entry.ts` filenames. The source inventory lists each family's files explicitly; native-family test and production matrices establish the functional behavior described in the affected rows.

Every row inherits the plan's missing/null/invalid data, external update, read-only/disabled/restrict, i18n, keyboard/focus, narrow layout, theme, and Web Component checks. “Test exists” means a file exists, not that all relevant scenarios pass.

### Native text input behavior

Ordinary text, multiline and suggested-string renderers keep the existing Flowbite
Input/Textarea, shadcn Input/Textarea and Skeleton styled native controls. Their
shared Svelte helper coordinates component reactivity, pending-edit registration
and disposal; it does not introduce a separate form-data model.

The React reference plain-text renderers currently pass schema `maxLength` to
HTML `maxlength`. The current spec requires Unicode code-point semantics, so the
Svelte renderers enforce completed edits instead of copying that UTF-16 limit.
Imported invalid strings remain intact until edited, and shortening an invalid
string toward validity is allowed. IME event sequences remain drafts until
composition ends. This behavior is separate from masks and password/OTP, whose
remaining composition acceptance is tracked under P3.3/P3.6.

Button activation now resolves the nearest pending-edit scope and waits for Svelte
to publish the resulting data and validation before invoking the action or script.
Unfinished composition and registered invalid drafts block consumption; disposing
the Button cancels preparation. Schema validation errors alone do not disable
arbitrary actions, which may exist to correct those errors.
