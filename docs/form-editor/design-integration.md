# Additional design integration — 2026-09-12

The owner supplied [JSONForms Visual Editor — Design Document](./additional-design.md). That file preserves the supplied text verbatim. Its “not yet implemented” status describes the supplied design, not the current repository. This page maps its requirements to the existing architecture and implementation backlog; it prevents conflicting descriptions from silently becoming competing implementations.

## Added or expanded target requirements

- Visual schema authoring is a first-class surface: schema tree add/rename/retype/reorder/nest/delete and constraint editing must work independently of canvas bindings or Monaco. Keep property ordering distinct from layout ordering.
- Make the target JSON Schema dialect configurable per document. Target draft-07, 2019-09, and 2020-12 with local meta-schemas, appropriate AJV configurations, and a centralized keyword-availability table for inspectors. Draft-07 remains the current implementation slice, not the final limit. Detect `$schema` on import; represent any explicit editor dialect selection consistently with it, and report conflicts rather than maintaining contradictory dialect identities. Changing dialect never silently rewrites or strips existing keywords.
- Include an explicit schema root node (`#`) and visual authoring for primitive and array roots. Guided object/array root conversion must be one undoable transaction, show its structural impact, and leave unresolvable UI scopes available for repair. Primitive-root duplicate binding should select the existing occurrence. Boolean schema documents and null-valued instance data remain supported by the existing preservation contract.
- Add a Definitions branch supporting both `definitions` and `$defs`, resolved reference summaries, Go to definition, Unlink, Extract to definition, and cycle-safe navigation. Retain the property's scope when binding a referenced schema; never substitute the definition's pointer as the control scope.
- Add `additionalProperties` and `patternProperties` editing, including boolean/schema alternatives, pattern validity feedback, and nested schema inspectors. Dynamic-key pseudo-nodes are not individually bindable; the containing object is. Runtime rendering can be supplied by a host descriptor/renderer.
- Organize JSON Forms-driven inspectors into General / Constraints / Rule / Options / Advanced sections as appropriate. Reference-node inspectors expose shared-definition actions. Schema-based rule conditions reuse the schema-constraint editing building blocks. Preserve unrecognized conditions on visual/raw mode switches.
- Add a bind-existing/create-new choice for palette drops, target-object resolution, and array-item shape authoring. Use a single typed drop dispatcher and a centralized allowed-parent table. Native drag-and-drop in the current slice is temporary; evaluate pointer-based nested drag/drop and accessibility before treating it as the final implementation.
- Ship English and Bulgarian editor catalogs, locale selection, fallback, and a CI key-parity check. Maintain the earlier separation of editor translations from authored form translations and the host-owned preference boundary.
- Formalize host-provided authoring/control definitions, shared descriptor metadata, and the authored UI-schema meta-schema. Monaco is the only code editor, including inline fragments. Source wrapper language configuration remains independent of human UI locale.
- Maintain purpose-specific components and feature subfolders. Keep shadcn source components unchanged; editor-specific wrappers and styling belong outside `components/ui`. Report any necessary change to the owner before modifying those shadcn sources.

## Phase mapping and completion gates

The existing [implementation plan](./implementation-plan.md) remains the execution checklist; the supplement's different phase numbering is a reference, not a second progress tracker.

1. Phase 0: add dialect/renderer descriptor contracts and package-boundary decisions, plus local Monaco meta-schema verification. Document exact shadcn source provenance.
2. Phases 1–3: preserve unknown fields in targeted commands; stabilize IDs, selection and history; complete schema-only editing and a complete bind/create transaction. Tests must exercise vendor keys through ordinary edits, not only load/save.
3. Phase 4: complete category/step and array-item authoring. Add primitive/array root fixtures and guided root conversion with undo and broken-scope diagnostics.
4. Phase 5: deliver draft-aware constraint forms; definition navigation/extract/unlink; dynamic-keyed object authoring; typed/composite/schema-based rule forms and Monaco fragments. Add draft-switch, circular-reference, regex, and unknown-condition preservation tests.
5. Phase 6: deliver host registration APIs, reusable UI-schema/template authoring and repository extension adapters. Ensure the same descriptor metadata feeds matching, palette, inspector and UI-schema completion.
6. Phase 7: deliver English/Bulgarian catalog coverage, locale/theme parity, keyboard and pointer workflows, packaging decisions, and final runtime/source fidelity checks. Ship nothing as complete merely because the first interactive demo works.

## Current implementation boundary

The current work is the first interactive slice: example selection, actual renderer samples within a structural canvas, basic layout/control insertion and movement, a small JSON Forms-driven inspector, snapshot undo/redo, Monaco document editing, and optional runtime preview. It is not completion of visual schema authoring, multiple dialects, stable node IDs, full rules, template authoring, localization, native package distribution, or the full property inspector. Those requirements remain on the mapped backlog above.

## Current package and workspace implementation

The native editor is `packages/jsonforms-svelte-editor`; custom-element registration, shadow-root hosting, renderer asset packaging and browser distribution belong to `packages/jsonforms-svelte-editor-webcomponent`. The demo has native Svelte and web-component integration modes. Both consume host-supplied form parts.

Follow additional-design.md §12 as the module blueprint: `editor/document`, `editor/dnd`, `editor/registrations`, `editor/components/Canvas`, `editor/components/Inspector`, and separate Monaco, preview and style modules. Add the planned submodules as their features land; do not create empty placeholder implementations.

Use `svelte-dnd-action` for pointer/keyboard dragging. Transient hover lists are separate from document state; final drops invoke immutable commands. Stable identities live in a WeakMap and survive command clones/history without entering exported JSON.

Resizable palette/schema-tree, schema-tree/canvas and canvas/inspector boundaries use the existing, unchanged shadcn resizable components backed by Paneforge. This follows the design's splitter requirement with the repository's existing implementation rather than introducing a second splitter library.

## Owner clarification: native inspector

Use native Svelte JSON Forms for the inspector, with the same host-defined shadcn sources as the editor UI. The native package imports the shared component alias; the demo and wrapper supply its mapping. Do not render the inspector through `jsonforms-svelte-shadcn` or maintain an independent component copy inside the native editor. See the architecture's shared-components contract. This is a confirmed requirement and takes precedence over any earlier runtime-adapter inspector wording.
